**Оценка: 70/100.** Полный пользовательский путь работает на трёх новых монолитах, но найдены ошибки анализа и редактора, которые мешают уверенно защищать семантическую корректность. ### Независимые оракулы

ClearingHouse проверяет проводки, резервирование точного остатка, откат после списания, reversal, дедупликацию, frozen-аккаунты, окно риска на границе, обход зависимостей и циклы, округления, денежные переполнения, конвертацию по цепочке, CSV с кириллицей, prefix sums и порядок suppressed exceptions. Для взаимозачёта используется отдельный массив дебетов/кредитов на случайных входах; он не вызывает реализацию compress.

QueryForge проверяет приоритеты арифметики и логики, short circuit с делением на ноль, NULL, функции, кавычки и позиции синтаксических ошибок, фильтр/сортировку/LIMIT, индексы после rollback, атомарность bulk insert при ошибке схемы, группировку, оконные суммы, median, immutable Row, set operations, многострочный CSV и закрытие курсора при continue. Hash join сверяется с независимым вложенным циклом на случайных таблицах с дублями и NULL.

TransitGrid сверяет Диница с полным перебором разрезов небольшого направленного мультиграфа; маршруты — с независимым Bellman–Ford; SCC — с взаимной достижимостью; Kruskal — с перебором подмножеств рёбер; Fenwick — с обычным массивом после случайных обновлений. Дополнительно проверены расписания, виртуальный ExpressLink, лимиты мест, тарифы, атомарный rollback бронирования, отмена, дубли, нулевой маршрут, полуоткрытые интервалы занятости и распределение мест.

## Найденные дефекты

Приоритет P1 — исправить до уверенной защиты основной функции; P2 — заметный дефект демонстрации/удобства. Это приоритеты аудита, не официальный severity организаторов.

### J01 · P1 · Валидный finally с единственным комментарием ломает весь разбор

Открыть [FinallyComment.java](../../../backend/examples/jury/FinallyComment.java). В finally есть только обычный комментарий. Java компилируется и печатает `work` / `after`, но POST `/projects/parse` возвращает **422 UNSUPPORTED_TRANSFORM: No data of this type found**. Исходник без комментария или с комментарием перед исполняемой строкой может проходить — условие дефекта именно comment-only/orphan comment, не любой комментарий.

В [ControlFlow.java](../../../backend/java-engine/src/ControlFlow.java#L184) finalRoute перебирает `findAll(Node.class)` и запрашивает `n.getData(ID)` у узла без присвоенного ID. Собственный шаблон палитры `try/catch/finally` содержит такой комментарий и падает по той же причине. **18 из 19 шаблонов разбираются; все 19 компилируются в подготовленном контексте.**

Исправить обход: пропускать комментарии/узлы без identity, сохранив identity настоящих AST-операторов. Добавить regression с пустым finally, line/block orphan comment и комментарием перед обычной инструкцией. Быстрый объём — ориентировочно 30–60 минут с проверками. [API](finally-comment-api.json), [реальный Java](finally-comment-java.json), [шаблоны](template-results.json).

### J02 · P1 · Alias StringBuilder занижает O(n²) до O(n)

В [CostTraps.aliasBuilder](../../../backend/examples/jury/CostTraps.java#L8) две переменные указывают на один StringBuilder. `first.append` увеличивает буфер, `alias.toString` копирует длины 1…n. Суммарная работа Θ(n²), статическая карточка выдаёт **O(n)** без unknown. Это ошибочная верхняя граница, а не просто отсутствие оценки.

Причина: размеры и эффекты роста привязаны к тексту переменной, а не общей абстрактной ссылке. Начать с [Complexity.java](../../../backend/java-engine/src/Complexity.java#L706): объявления/присваивания, `sizes`, `growth`, `linearReads`, `linearSize`. Нужны alias-группы для mutable объектов и единое обновление размера на всех ссылках. До полноценного исправления безопаснее unknown при неразрешённом alias. Проверить также alias через поле и параметр. Порядок объёма: несколько часов, не косметическое изменение.

### J03 · P1 · Рост списка через helper скрывает кубический обход

[CostTraps.growingHelper](../../../backend/examples/jury/CostTraps.java#L21) n раз добавляет n элементов, затем проходит весь накопленный список. Число посещений равно **n²(n+1)/2**, то есть Θ(n³). JUnit проверяет точное число на размерах 0…32. Анализатор выдаёт **O(n²)**.

Межпроцедурный эффект роста передаётся, но размер loop-carried коллекции при расчёте последующего foreach не отражает рост между внешними итерациями. Проверить [propagateGrowth](../../../backend/java-engine/src/Complexity.java#L445), обработку foreach и эффекты summarize/methodCall. Нужен расчёт состояния на границе внешнего цикла либо консервативная верхняя граница по максимальному размеру; при неизвестном эффекте — unknown. Отдельные regression: helper до foreach, после foreach, через alias, два последовательных внешних цикла.

### J04 · P1 · Неявные NPE не проходят через finally на схеме

[boxedSwitch и unboxing](../../../backend/examples/jury/CostTraps.java#L41): `switch(Integer)` с null и `value + 1` при null обязаны выполнить finally и затем бросить NPE. Два настоящих JUnit-теста это подтверждают. В IR у соответствующих return нет ребра неявного исключения; показано нормальное продолжение.

В [ControlFlow.mayThrow](../../../backend/java-engine/src/ControlFlow.java#L100) нет полноценной модели типов/распаковки и null selector. Добавить маршруты для boxed switch, арифметической распаковки, Boolean в условии и return с распаковкой; учитывать `case null`. Текущий механизм finally уже может провести исключение, когда оно обнаружено. Это ограничение обязательного scope с обёртками, несмотря на поддержку синтаксиса record/switch как бонуса. [API и IR-доказательства](api-results.json).

### J05 · P1 · Два клика «Переменная» создают некомпилируемый Java

Импортировать пустой `public static void main(String[] args) {}`. Дважды нажать «Переменная (примитив/обёртка)», затем Run. Обе операции сохранения возвращают 200; javac сообщает **variable value is already defined**. Старый тест store вызывает addNode без customCode и потому не проверяет реальный путь кнопки.

В [ProjectExplorer](../../../frontend/src/components/layout/ProjectExplorer.tsx#L250) передаётся defaultCode, а [addNode](../../../frontend/src/store/useProjectStore.ts#L433) обеспечивает уникальность только при `!customCode`. Отличать стандартный шаблон от произвольного пользовательского кода, передавать ID шаблона и нормализовать имена с учётом scope. То же проверить для повторных Scanner/List/Map/массивов. Быстрое исправление с браузерным regression — примерно 1–2 часа. [Источник и javac](palette-results.json), [скриншот](palette-duplicate.png).

### J06 · P2 · PNG экспорт теряет обычные стрелки

В браузере линии видны, скачанный PNG содержит узлы и пунктирные маршруты исключений, но обычные связи отсутствуют. Недостаточно проверять сигнатуру PNG и размеры: эти smoke checks успешно прошли. Дополнительная проверка пикселей в трёх точках каждой обычной линии нашла **4 из 4 отсутствующих линий** на стандартном main. Дефект также виден на экспорте QueryForge.

Проверить [export-image.ts](../../../frontend/src/lib/export-image.ts#L105): computed fill/stroke сейчас фиксируются только для фона блоков. Зафиксировать вычисленные stroke/stroke-width/fill и нужные CSS-переменные у edge paths/markers при клонировании, восстановить исходные стили после экспорта. Обязательно сравнить light/dark и нормальные/условные/exception рёбра. Оценка объёма — 1–2 часа. [Браузер](png-browser.png), [плохой PNG](png-export.png), [точки и измерение](png-results.json).

### J07 · P2 · «Метод / Конструктор» обещает неподдержанную операцию

В открываемой форме ввести `public PaletteProbe()`. Backend отвечает **422: поля, конструкторы и дополнительные классы здесь не допускаются**. Существующие конструкторы импортируются, но эта панель их не создаёт. Нужно либо добавить отдельный режим создания/проверки конструктора, либо честно переименовать пункт в «Метод». Это несогласованность подписи и поведения. [Ответ API](palette-results.json), [форма](palette-constructor.png).

### J08 · P2 · Распознавание Big O резко падает на обычных составных программах

**98 из 229** методов/конструкторов получили unknown. Часть — ожидаемые абстрактные тела и сложные рекуррентные алгоритмы, но значительная часть связана с обычными `Math.addExact/multiplyExact/floorMod`, `Collections.unmodifiable*`, `Map.Entry`, EnumSet, `removeIf`, форматированием и SuperExpr. Неизвестный простой leaf-вызов распространяется на большие методы запуска. Значение 99/100 в предыдущем MissionControl не является характеристикой произвольного монолита.

Добавить ограниченные проверяемые JDK-контракты, сохраняя стоимость callback, сравнения и объёма строк. Для Диница/Pratt parser допустим unknown; нельзя заменять его угаданным O(n). Отдельно показывать пользователю точную причину unknown и число внешних символических контрактов. Этот пункт требует последовательного расширения модели, не одного патча.

## Что выдержало проверку

Все 229 отдельных схем открыты в живом браузере: геометрических наложений не обнаружено. Для каждого проекта проверены импорт, точный .java экспорт, добавление и удаление реального метода, переход в исходник, разграничение основного и тестового файла, запуск Java, показ JUnit и сравнение с оригиналом. 24 браузерных smoke checks пройдены; их PNG-проверка подтверждала только формат, семантический дефект экспорта обнаружен отдельно. [ClearingHouse](clearing/browser.json), [QueryForge](query/browser.json), [TransitGrid](transit/browser.json).

Неверный исходник и ошибочный batch не меняют сохранённый проект. Stale revision даёт 409, traversal и неизвестные поля JSON отклоняются, generate сохраняет исходник. Gate ИИ отклоняет компилируемую мутацию комиссии и не повышает revision. Мутация не меняла stdout на выбранном пустом сценарии, но была поймана JUnit — полезная проверка, что сравнения одного вывода недостаточно.

Один настоящий запрос к настроенному ИИ получил 200 примерно за 8,6 секунды: модель правильно нашла квадратичность aliasBuilder, revision и исходник не изменились. Это подтверждает работоспособность одного запроса, а не качество всех будущих ответов. [Ответ и состояние](ai-smoke.json).

Быстрые backend-проверки по-прежнему проходят: 27 групп примерно за 16,6 секунды на машине разработки, TypeScript проходит. Большие примеры, JaCoCo, мутации и браузерные аудиты не добавлены в per-push CI. [Лог](backend-ci.log).

## Что исправлять первым

1. J01 и J05: устранить видимые отказы на валидном коде и двух простых кликах. Добавить regression именно через фактический UI-путь.
2. J02–J04: убрать неверные обещания сложности и отсутствующие исключительные маршруты; неизвестное состояние показывать явно.
3. J06 и J07: восстановить экспорт и привести подписи к возможностям перед демонстрацией.
4. J08: расширять leaf-контракты на новых корпусах, сохраняя отрицательные примеры.

Указанные сроки — приблизительная оценка объёма, не гарантия. Поднимать оценку нужно после прохождения этих воспроизводимых проверок, а не после уменьшения количества unknown любым способом.

Инструкция запуска и ограничения языков примеров: [backend/examples/jury/README.md](../../../backend/examples/jury/README.md). Контрактные команды намеренно красные на проверенной версии; это не поломанные тестовые монолиты. Проверка всех 229 методов и покрытие исполнения не означают исчерпывающего доказательства всех возможных состояний Java.
