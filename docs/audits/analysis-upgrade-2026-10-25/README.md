Проверены прежние исходники без упрощения алгоритмов: `MissionControl.java` (1 566 строк, 100 методов и конструкторов), его 16 JUnit-тестов и складской `Main.java` с 12 тестами. Для семантики исключений добавлен отдельный [FlowCases](../../../backend/examples/analysis-conformance/FlowCases.java) с 10 настоящими JUnit-тестами. Исторические отчёты сохранены отдельно: [исходные ограничения](../mission-control-2026-10-25/README.md).

## Результат анализа

| Показатель MissionControl | До | После |
| --- | ---: | ---: |
| Оценки Big O | 4 / 100 | 99 / 100 |
| `unknown` | 96 | 1 |
| Формулы с явным внешним C(callback) | — | 4 |

99 оценок — **условные верхние границы**, а не 99 доказательств точной сложности. Четыре обобщённых метода репозитория оставляют стоимость пользовательской функции/интерфейса явной переменной `C(...)`. Единственный `unknown` — объявление `Identified.id()` без тела: открытая реализация не имеет определённой стоимости. Размер результата, который нельзя вывести, может фигурировать отдельным символом. Его размер не подменяется временем вычисления. Полные формулы и предположения сохранены в [analysis.json](analysis.json).

Распознаются вызовы методов проекта с подстановкой размеров аргументов, конструкторы, generics и record-accessor, известные виртуальные реализации, возвращаемые коллекции, рост строк и коллекций между вызовами, потоки и callback, рекуррентные соотношения и некоторые обходы графов. Предел анализа и непроверенные условия приводят к `unknown` или явному контракту, а не к автоматическому `O(1)`.

| Пример из монолита | Полученная оценка |
| --- | --- |
| lowerBound | O(log n) |
| mergeSort | O(n log n) |
| longestIncreasing | O(n²) |
| knapsack | O(capacity × n) |
| nextGreater, монотонный стек | O(n) |
| geometricWork, сумма уменьшающихся объёмов | O(n) |
| fibonacci через проверенный wrapper и общий кэш | O(n) |
| fibonacciMemo без ограничения wrapper | консервативная экспоненциальная граница |
| Дейкстра | очередь O((V + E) log(V + E)) плюс стоимость проверок рёбер |

Цена проверок рёбер включает используемые коллекции: HashSet/HashMap получают консервативную границу при коллизиях; наличие хеш-таблицы не превращает её операции в безусловный O(1). `PriorityQueue.remove(Object)` и `contains` линейны, извлечение головы логарифмично; это различие проверяется отдельно. Контракты взяты из документации [PriorityQueue](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/PriorityQueue.html) и [ArrayList](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/ArrayList.html).

## finally и ресурсы

Граф хранит отдельные продолжения для нормального выхода, `return`, `throw`, `break` и `continue`, включая метки и вложенные `finally`. Значение `return` вычисляется до очистки; новый `return` или `throw` из `finally` отменяет прежнее продолжение. Копии блока на разных маршрутах ссылаются на один AST: редактирование любой копии меняет исходный Java-код и остальные копии.

Ресурсы открываются слева направо и закрываются справа налево. Ошибка инициализации закрывает только ранее открытые ресурсы. Ошибка закрытия при основном исключении добавляется в suppressed; без основного исключения она заменяет ожидаемый выход. Для null-ресурса закрытие пропускается. Отдельно проверено самоподавление одного Throwable. Порядок следует [JLS §14.20.2](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.20.2) и [§14.20.3](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.20.3).

Это анализ потока внутри метода. Для неизвестных типов исключений из вызовов граф консервативно оставляет несколько возможных маршрутов; он не утверждает, что каждый из них выполним. Внутренний поток лямбд и switch-выражений пока не развёрнут. Длинные формулы доступны в раскрываемой карточке, служебные узлы очистки не дублируют метрики исходника.

## Проверка

Быстрый набор содержит 27 групп backend-проверок и один frontend-тест; большие программы и браузерные проверки запускаются вручную. Негативные примеры проверяют переполнение счётчиков, меняющиеся границы и массивы, неверную середину бинарного поиска, растущий alias коллекции, дорогой toString, диспетчеризацию в подкласс, рекурсию с поздним/условным базовым случаем и очередь без гарантированной пометки. В проверке finally отсутствие обходного пути тестируется отдельно от простой достижимости.

Реальный javac/JUnit запускается в Docker. Совпадение вывода на выбранных входах не является доказательством эквивалентности всех программ. Счётчик распознанных оценок не используется как замена негативным тестам.

Команды воспроизведения:

```bash
npm --prefix backend run setup
npm --prefix backend run test:ci
npm --prefix backend run check:analysis
npm --prefix backend run stress:mission
npm --prefix backend run test:browser
npm --prefix backend run stress:mission:browser
```

Подробные результаты прогонов, геометрия 100 методов, проверки правок, мутации и снимки экрана приложены в этой папке.

Фактически выполнено локально: 27 backend-групп за 14,0 с, 5 браузерных сценариев за 39,4 с, 100 отдельных схем без наложений, редактирование копии finally через интерфейс с 10 успешными JUnit-тестами. Backend/frontend TypeScript, сборки и проверка шлюза пройдены. Линтер оставляет прежнее предупреждение об escape в `aiAnalyzer.ts`; сборщик — прежнее предупреждение о размере bundle.

Складской код также сохранён и проверен: три безопасные правки не изменили вывод, обе мутации провалили 12 тестов, добавление/удаление метода сохранило поведение. Его покрытие Big O составляет **51 из 72 методов/конструкторов**, то есть результат 99/100 относится именно к MissionControl. Нераспознанные библиотечные контракты, некоторые циклы с continue/do-while и генерация уникальных случайных значений требуют дальнейшего анализа, а не замены `unknown` предположением.
