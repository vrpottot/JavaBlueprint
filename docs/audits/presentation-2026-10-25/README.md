# Повторная проверка перед презентацией · 25 октября 2026

Это новый прогон после [исходного аудита с оценкой 70/100](../jury-2026-10-25/README.md). Старые результаты сохранены отдельно. Проверяемая версия Java engine — `c28675f`; интерфейс — `459b93e`. Скриншоты сняты с настоящего локального приложения. Формулы сверены через API, пользовательский Java выполнялся только в ограниченных Docker-контейнерах.

Таблица показывает количество условных оценок `estimated`, а не процент доказанной корректности. 78 методов нового корпуса остаются `unknown`. В MissionControl оставшийся случай — абстрактный метод без тела; четыре оценки имеют явную зависимость от стоимости callback.

[Полные оценки и предположения](analysis.json). Отдельно проверены ошибки занижения: alias растущего StringBuilder теперь получает **O(n²)**, helper с ростом списка перед повторными обходами — **O(n³)**. Регрессии также проверяют индексный обход, два параметра с общим объектом и безопасный переход к `unknown` при перепривязке объекта с живыми alias.

## Чего результат не доказывает

Прохождение выбранных тестов не доказывает полную эквивалентность Java-программ. Новые контракты не означают полное покрытие JDK, а поддержка прямых alias не заменяет общую heap-модель. Граф по-прежнему имеет документированные непрозрачные конструкции. Новая оценка 100/100 не заявляется; [конкретные критерии и оставшаяся работа](../../QUALITY_ROADMAP.md) вынесены отдельно.
